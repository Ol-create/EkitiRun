# EkitiRun

Race platform for the Ekiti Marathon: free runner registration, sponsor payments, checkpoint timing and real-time GPS tracking of every runner.

## Requirements

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (on Windows, with the WSL 2 backend)
- [Node.js](https://nodejs.org/) 22 (LTS) and [pnpm](https://pnpm.io/installation) 12: run `npm install -g pnpm@12`
- [Git](https://git-scm.com/downloads). On Windows, Git Bash or PowerShell both work for the commands below
- Optional, for running the API outside Docker: Python 3.12+ and [uv](https://docs.astral.sh/uv/): run `pip install uv`

The exact pnpm version is pinned in `package.json` (`packageManager`), and dependency versions are locked in `pnpm-lock.yaml` and `apps/api/uv.lock`. Don't delete the lockfiles.

## Getting started

### 1. Clone and create env files

```bash
git clone <repo-url> ekitirun
cd ekitirun
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env.local
```

Never commit `.env` files. They are ignored by git.

### 2. Start the backend (Postgres, Redis, API, worker)

```bash
docker compose up -d
```

The first run takes a few minutes while images download and build. When it is done:

| Service | URL / port | Notes |
|---|---|---|
| API | http://localhost:8000 | Reloads automatically when you edit files in `apps/api` |
| API docs (Swagger) | http://localhost:8000/docs | |
| Health check | http://localhost:8000/health | Returns `{"status": "ok"}` |
| Worker | none | ARQ jobs: invoice and receipt PDFs |
| Postgres | `localhost:5433` | user, password and database are all `ekitirun`. Port 5433 on your machine, so it doesn't clash with a locally installed Postgres; inside Docker it is `db:5432` |
| Redis | `localhost:6379` | |

All feature routes live under `/api/v1`.

### 2b. Create the tables and load the sample data (first run, and after pulling new migrations)

```bash
docker compose exec api alembic upgrade head
docker compose exec api python -m scripts.seed
```

The seed loads the four race categories, a **placeholder course** around Ado-Ekiti and its checkpoints. It is safe to run again.

### Fake API (Phase 0 stubs)

Until each feature is built for real, most endpoints return **fake data** from a simulated race that moves on a clock, so the leaderboard, maps and live streams change like a real race. `GET /categories` already reads the real database. The rules for triggering errors (OTP codes, phone numbers that are "already registered", failed payments, admin token) are in [docs/api-contract.md](docs/api-contract.md#phase-0-stub-behaviour).

### 3. Start the frontend

```bash
pnpm install
pnpm dev
```

Open http://localhost:3000.

## Environment variables

### API (`apps/api/.env`)

| Variable | Example | Purpose |
|---|---|---|
| `DATABASE_URL` | `postgresql+asyncpg://ekitirun:ekitirun@db:5432/ekitirun` | Postgres connection. Use host `db` inside Docker, `localhost` outside it |
| `REDIS_URL` | `redis://redis:6379/0` | Redis for the worker queue. Use host `redis` inside Docker, `localhost` outside it |
| `JWT_SECRET` | `dev-only-jwt-secret-at-least-32-characters` | Signs phone-verification tokens and hashes OTP codes. Production: 32+ random characters |
| `QR_SIGNING_SECRET` | `dev-only-qr-secret-at-least-32-characters` | Signs runner QR codes. Production: 32+ random characters |
| `PAYMENT_PROVIDER` | `fake` | `fake` approves every checkout without Paystack (an email containing "fail" fails), for local work. `paystack` uses the real API; production requires it with a `sk_live_` key |
| `PAYSTACK_SECRET_KEY` | | Paystack secret key: `sk_test_...` for test mode. Also verifies webhook signatures |
| `SMS_PROVIDER` | `console` | `console` prints SMS to the API log instead of sending; production must use `termii` |
| `TERMII_API_KEY` | | Termii SMS key. Leave empty locally |
| `RACE_DATE` | `2027-03-06` | Race day, for the minimum-age rule. Empty = today. A category's gun start time overrides it |
| `ORGANISER_NAME`, `ORGANISER_ADDRESS`, `ORGANISER_EMAIL` | | Shown on sponsor invoices and receipts |
| `BANK_NAME`, `BANK_ACCOUNT_NAME`, `BANK_ACCOUNT_NUMBER` | | The organisers' account, printed on invoices for sponsors paying by bank transfer |
| `OTP_DEV_CODE` | `123456` | Development only: every OTP is this code. Empty = random codes, printed in the API log |
| `TERMII_SENDER_ID` | `EkitiRun` | SMS sender name |
| `CORS_ORIGINS` | `http://localhost:3000` | Allowed frontend origins, comma-separated: `http://localhost:3000,https://ekitirun.ng` |

With `ENVIRONMENT=production` the API **refuses to start** if a secret is a development value or shorter than 32 characters, `OTP_DEV_CODE` is set, or SMS isn't going through Termii.

After changing `apps/api/.env`, restart the services so they pick it up:

```bash
docker compose up -d --force-recreate api worker
```

### Working on the API

- Python code changes reload automatically; you only rebuild when dependencies in `apps/api/pyproject.toml` change.
- Each feature lives in `apps/api/app/modules/<feature>/` with its own router, schemas, service and tests.
- After you change an endpoint or schema, run `pnpm gen:api` so `apps/web/lib/api-types.ts` matches, and commit both.

### Running API tests and lint

Outside Docker, from `apps/api`:

```bash
uv sync
uv run pytest
uv run ruff check .
```

`uv sync` installs the dev tools (pytest, ruff, mypy). PDF rendering needs WeasyPrint's system libraries (Pango); if they are missing on your machine, run tests in Docker instead:

```bash
docker compose exec -e TEST_DATABASE_URL=postgresql+asyncpg://ekitirun:ekitirun@db:5432/ekitirun_test api sh -c "uv pip install --system pytest pytest-asyncio && pytest"
```

## Checkpoint scanner (`/scanner`)

Volunteers open `/scanner` on a phone, enter their checkpoint's 6-digit PIN, and scan bib QR codes (or type bib numbers). Every scan is saved on the phone first and uploaded every 10 s when there is signal, so scanning works with no network at all.

- **Make the PINs** (once, after seeding; printed only once, so save them): `docker compose exec api python -m scripts.checkpoint_pins`. `--reset-all` replaces every PIN.
- **Before the race**, each volunteer opens `/scanner` once *with signal* and logs in: that downloads the runner list and, in production builds, stores the page for offline use. After that the phone can be offline all day; a login lasts 24 hours.
- **Phones need HTTPS** for the camera (browsers block it on plain `http://`, except `localhost`). The deployed site has HTTPS; for testing on a phone locally, use a tunnel such as `ngrok http 3000`.
- Scans that couldn't be uploaded stay on the phone, even after logging out or closing the browser, and upload after logging in to the same checkpoint again.
- **Phone clocks:** each upload measures how far the phone's clock is off, and timing corrects for it. Phones off by more than 2 minutes are listed first in `GET /api/v1/scanner/devices` (admin): ask that volunteer to turn on automatic date and time.

## Race-day timing

Times and places come from checkpoint scans (the timing engine, `app/modules/timing`).

- **Record each gun start** the moment the gun goes: `POST /api/v1/admin/categories/{id}/gun-start` with `{}` (= now), or `{"at": "2027-03-06T06:30:00+01:00"}` to set it afterwards. Every elapsed time counts from it; changing it later recalculates everything.
- **Did not finish:** `POST /api/v1/admin/runners/{bib}/dnf` (and `DELETE` to undo a mistake).
- Phone clock drift is corrected automatically, and when a runner is scanned twice at a checkpoint the earliest time counts.
- The leaderboard is cached in Redis and refreshes after every scan upload, so spectators never load the database.
- **Live updates:** every accepted scan is published on the Redis channel `scans` and pushed to browsers on `GET /api/v1/stream/results` (Server-Sent Events, `?category=` for one race). Each API process keeps one Redis subscription and fans events out to all its viewers. Any proxy in front of the API must not buffer `text/event-stream` responses.

## GPS trackers

Every runner wears a GPS tracker, handed out at kit collection. **Checkpoint scans stay the official timing; GPS only drives the live maps.**

    trackers --> Traccar (gateway) --> POST /api/v1/gps/traccar --> Redis stream --> gps-writer --> Postgres

- **`gps-writer`** (always running in Docker Compose) moves points from the Redis stream into Postgres in batches. It keeps only points from trackers assigned to a runner, notes where each point falls on the course, and flags points more than 200 m off the course (stored, never shown). One writer handled about 5,000 points/s in testing; race day needs about 1,000 (5,000 runners every 5 s). Run more writers if needed: they share the stream.
- **Traccar** receives each tracker's own protocol and forwards positions to the API. Locally it's optional: copy `infra/traccar/traccar.example.xml` to `infra/traccar/traccar.xml`, set the gateway secret in it, then `docker compose --profile gps up -d`. Web UI: http://localhost:8082. Without trackers, the free Traccar Client phone app (OsmAnd protocol, port 5055) is a handy test device.
- **Privacy:** location history is deleted 30 days after it was recorded (nightly job in the `worker` service).

### Tracker field test (before buying in bulk)

Test about 10 units of the shortlisted tracker on the real course, carried at running pace:

1. **Fix interval:** can it report every 5 to 10 s? Check the gaps between points in Traccar.
2. **Battery:** still reporting after 6+ hours at that interval (the slowest marathoners plus kit-collection time).
3. **Signal:** points arrive on every stretch of the course (look for gaps on the map), on the SIM network you'll use.
4. **Accuracy:** points stay within about 20 m of the course (`off_route_m` in `gps_positions`).
5. **Protocol:** Traccar supports it (most do); open that protocol's port in `docker-compose.yml`.
6. **Practicalities:** how it's worn (bib clip or armband), charging 5,000 units, labelling (`TRK-0001`), data-SIM costs.

## Background jobs and PDFs

The `worker` service runs background jobs (ARQ, using Redis): sponsor invoices are rendered when a pledge is created and receipts when it is paid. Every 5 minutes it also renders any document that was missed. PDFs are stored in Postgres and served at `/api/v1/files/...`.

- Follow the worker: `docker compose logs -f worker`
- Preview the invoice and receipt templates without a database: `cd apps/api && python -m scripts.render_pdf_preview` (writes `apps/api/pdf-preview/`)

## Paystack setup (sponsor payments)

- **Locally**, leave `PAYMENT_PROVIDER=fake`: checkouts go straight to the thank-you page and succeed, so no Paystack account is needed.
- **Test mode:** set `PAYMENT_PROVIDER=paystack` and a `sk_test_...` key, then pay with Paystack's test cards. Paystack can't reach `localhost` with webhooks, so locally the pledge is settled when the thank-you page checks its status (`sync_pledge`). To test real webhooks, expose the API with a tunnel (for example `ngrok http 8000`) and use its URL below.
- **Webhook URL** (Paystack dashboard, Settings > API Keys & Webhooks): `https://<api host>/api/v1/webhooks/paystack`. Set it for test and live mode separately.
- **Production:** `PAYMENT_PROVIDER=paystack` with the `sk_live_...` key; the API refuses to start otherwise. Turn on "Pay with Transfer" in the dashboard so large sponsors can pay by bank transfer.

## Troubleshooting

**`request returned 500 Internal Server Error ... dockerDesktopLinuxEngine`**
Docker Desktop's engine isn't running properly. Quit Docker Desktop, run `wsl --shutdown`, start Docker Desktop again and wait for "Engine running". If it keeps happening, update Docker Desktop.

**`error parsing value for field "cors_origins"`**
You are on an old version of `app/core/config.py`. Pull the latest code. `CORS_ORIGINS` is a plain comma-separated list, not JSON.

**`port is already allocated` (5433, 6379 or 8000)**
Something else on your machine uses that port, often a local Redis. Stop it, or change the left-hand port in `docker-compose.yml` (for example `"6380:6379"`) without committing that change.

**Docker Desktop shows an error and quits: `removing stale socket ... userAnalyticsOtlpHttp.sock`**
A known Docker Desktop bug. Quit Docker Desktop, run `wsl --shutdown`, delete `%LOCALAPPDATA%\Docker\run\userAnalyticsOtlpHttp.sock`, then start Docker Desktop again. Updating Docker Desktop fixes it for good. Don't pick "Reset to factory defaults" unless the rest fails: it deletes your images and volumes.

**Running API tests without Docker**
Database tests look for Postgres at `localhost:5433` (database `ekitirun_test`, created automatically) and are skipped if it isn't there. Point them elsewhere with `TEST_DATABASE_URL=postgresql+asyncpg://user:pass@host:port/ekitirun_test`.

**API container keeps restarting**
Run `docker compose logs api` and read the last traceback. It is usually a missing or wrong value in `apps/api/.env`.

**Frontend can't reach the API (CORS or network errors)**
Check that the API is up at http://localhost:8000/health, that `NEXT_PUBLIC_API_URL` points to it, and that your frontend's origin is in `CORS_ORIGINS`.
